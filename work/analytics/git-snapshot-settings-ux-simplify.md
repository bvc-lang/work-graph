# AN-83: Git Snapshot в настройках — непонятен обычному пользователю

**Запрос:** обычный пользователь не поймёт текущие настройки Git Snapshot («Записывать SHA в evidence», чекбоксы `done`/`status`/`created`/`analytics`). Если можно — включить всё по умолчанию и убрать блок из «Настройки». Изучить и сохранить разбор.

**Дата:** 2026-06-07

**Связано:** [AN-71](work-graph-git-autocommit-on-events.md), `epic-workgraph-git-snapshot-v1`, `wire-git-snapshot-settings-ui`

---

## Краткий вывод

Секция **Git Snapshot** в «Настройках» — **инженерный пульт** из AN-71, а не пользовательская опция. Обычный оператор не понимает SHA, evidence, scoped commit и английские имена событий.

**Рекомендация:** **убрать секцию из UI** и зашить политику в рантайм. Автокоммит **только на два события:** **`done`** (задача выполнена) и **запись разбора** (`analytics.created`). Ни `status`, ни `created` — без коммита. Статус — только UI доски. Отключение — через env или `.work-graph/git-snapshot.json`.

---

## Поправка: статус ≠ коммит

В черновике AN-83 ошибочно смешаны **смена статуса** (`ready` → `doing` → `in_progress`) и **git snapshot**. Это разные слои:

| Слой | Что делает | Git |
|------|------------|-----|
| **Статус** | Колонка доски, claim, перевод в работу — UX и очередь оператора | **Не нужен** отдельный коммит на каждый клик |
| **Задача выполнена** | Перевод в `done` / `complete_work_item` | **Да** — scoped commit + SHA в свидетельствах |
| **Запись разбора** | `seed:analytics-record`, новый AN в `work/analytics/` | **Да** — commit по md + journal |
| **Остальное** | Создание задачи, смена статуса, claim | **Нет** — только файлы для UI/канона |

Почему в v1 они оказались рядом: в AN-71 хук `work_item.status` заложен для MCP `update_work_item_status` и `claim_work_item` — технически при persist патчится `.bvc`, и инженерный пульт позволил включить коммит и на это. Для продукта это **лишний шум** (десятки коммитов «перетащил карточку»).

**Правило (уточнение оператора):** автокоммит на **`work_item.done`** и **`analytics.created`** (запись разбора). Без коммита: `status`, `created`, `claim` и прочие переходы по доске.

Текущий default в коде уже совпадает (`done` + `analytics`), но UI даёт лишние чекбоксы (`status`, `created`) — при рефакторинге убрать пульт из настроек и отрезать snapshot на status/created в handlers.

## Что видит пользователь сейчас

| Элемент UI | Текст | Почему непонятно |
|------------|-------|------------------|
| Заголовок | Git Snapshot | Жаргон продукта, не «сохранение в git» |
| Переключатель | Автокоммит (opt-in) | «opt-in» — английский термин; не ясно, что коммитится и когда |
| Переключатель | Записывать SHA в evidence | SHA, evidence — внутренние понятия WG |
| Подпись | scoped commit, no push v1 | Технический контракт протокола |
| Чекбоксы | done, status, created, analytics | Имена хуков, не действия пользователя |

По умолчанию всё **выключено** (`enabled: false` в `DEFAULT_GIT_SNAPSHOT_POLICY`, `src/gitSnapshot.mjs`). Пользователь, не зная про фичу, **не получает** ни автокоммитов, ни SHA в свидетельствах — хотя для него это могло бы быть «просто работает».

## Зачем выносили в настройки (AN-71)

1. **Opt-in, не тихий commit** — автокоммит не должен включаться скрыто: риск шума в истории, неожиданных коммитов в dirty tree, конфликта с привычкой «коммит только когда я сказал».
2. **Прозрачность** — оператор явно видит: push в v1 не делается.
3. **Гранулярность** — разные команды хотят коммиты только на `done`, без `status`.
4. **Конфиг без правки env** — запись в `.work-graph/git-snapshot.json` через UI.

Это оправдано для **внедрения v1** и dogfooding в WG-engine. Для **продуктового UX** после стабилизации контракта — избыточно.

## Можно ли «включить всё по умолчанию и убрать из настроек»?

### Да, с оговорками

| Параметр | Включить по умолчанию? | Комментарий |
|----------|------------------------|-------------|
| `enabled` | **Да**, если есть `.git` | Вне git-репозитория snapshot и так skip; не пугать пользователя |
| `events` | **`done` + `analytics.created`** | Задача выполнена и запись разбора. `status`, `created` — **нет** |
| `recordShaInEvidence` | **Да** | Польза для оператора: в задаче видна ссылка на коммит, без знания что такое SHA в настройках |
| `push` | `never` | Уже зашито, не настраивать |
| `requireCleanSubset` | `true` | Уже зашито — только paths из persist |
| UI в Настройках | **Убрать** | Обычному пользователю не нужен |

### Ограничения (не снимаются defaults)

- Snapshot **не блокирует** закрытие задачи при ошибке git (AN-71).
- **Не** `git add -A` — только явные paths.
- **Не** push.
- Pre-commit hook может **отклонить** commit → evidence «snapshot failed», задача всё равно `done`.

### Риск «включено по умолчанию»

| Риск | Серьёзность | Митигация |
|------|-------------|-----------|
| Много мелких коммитов | Средняя | не коммитить на `status`; только смысловые события |
| Пользователь не ожидает коммитов | Средняя | Коммиты только WG-файлов (intent, analytics), не весь diff IDE |
| Агент Cursor «не коммитить» | Низкая | Правило агента ≠ поведение WG; коммитит только WG-hook |
| Не git-репозиторий | Нет | skip без ошибки |

**Итог:** включение по умолчанию **допустимо** при условии «только WG-файлы, без push, без блокировки done». Убрать из настроек — **правильно**.

## Целевое поведение (предложение)

### Для обычного пользователя

- В «Настройках» **нет** секции Git Snapshot.
- При работе в git-репозитории WG **сам**:
  - при **закрытии задачи (`done`)** — scoped commit + SHA в «Свидетельствах»;
  - при **записи разбора** — scoped commit по `work/analytics/*.md` и `analytics-records.jsonl`;
  - создание задачи, смена статуса на доске — **без** автокоммита.

### Для продвинутого / CI

- `WORKGRAPH_GIT_SNAPSHOT=0` — выключить полностью.
- `WORKGRAPH_GIT_SNAPSHOT_EVENTS=done,analytics` — урезать события.
- `.work-graph/git-snapshot.json` — как сейчас, но **без UI** (ручное редактирование или будущий CLI).

### Если когда-нибудь вернуть в UI

Один переключатель на человеческом языке, без подпунктов:

> **Сохранять в git при выполнении задачи и записи разбора**  
> Коммит при «Готово» и при сохранении аналитического разбора. Локально, без отправки на сервер.

Без чекбоксов событий, без «SHA в evidence».

## Предлагаемые defaults в коде

```javascript
// src/gitSnapshot.mjs — целевые DEFAULT (после задачи)
{
  enabled: true,  // фактически: true если .git существует
  events: ['work_item.done', 'analytics.created'],
  recordShaInEvidence: true,
  push: 'never',
  allowEmpty: 'skip',
  requireCleanSubset: true,
}
```

Файл `.work-graph/git-snapshot.json` и env **перекрывают** defaults (для отключения).
