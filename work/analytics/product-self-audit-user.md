# AN-7: Продуктовый аудит Work Graph Rebuild (взгляд пользователя)

**Запрос:** «нужен критический анализ текущего продукта не с технической точки зрения, а с пользовательской: зачем мне этот продукт, в чём его идея, какую боль решает, какие аналоги решают эту боль лучше».

## 1. Идея, как она читается из артефактов

Из `charter/main.bvc` и `README.md`:

> Минимальная **agentic engineering OS**, где задача проходит путь от намерения до verified evidence через Work Graph, а не через свободный чат.
>
> Эталонный сценарий: `charter.bvc → Work Graph task → agent claim/execute → code change → trace/evidence → verification → memory update`.

Переводя на человеческий: **«Сделать разработку с LLM-агентом не чатом, а обходимым графом задач со следом, который не забывается между сессиями».**

Узнаваемая боль: чат-агент пишет код, через неделю никто не помнит почему — приходится начинать заново. Work Graph хочет: каждое решение — атом со ссылкой на намерение, evidence и проверку.

## 2. Какую боль продукт **думает**, что решает

| Заявленная боль | Реальность боли |
|---|---|
| Свободный чат теряет контекст | да |
| LLM «галлюцинирует» — нет evidence | да |
| Память проекта живёт в голове / Confluence / нигде | да |
| Намерение → код → проверка не связаны | да |
| 1C/OneBase разработка без LLM-tooling | да, но узко |

## 3. Какую боль продукт **на самом деле** решает сегодня

Жёстко: **боль автора в том, чтобы кодировать в своём каноне**. Это не цинизм — нормальная фаза R&D. Но это **не пользовательская боль**.

Чтобы доказать пользовательскую ценность, нужно, чтобы хотя бы один человек, не являющийся автором:
- открыл продукт без обучения;
- провёл задачу через эталонный сценарий;
- получил измеримый результат (быстрее / точнее / понятнее).

Сейчас этого пути нет: `README.md` обрывается на seed-фазе, нет демо, нет «getting started», UI русскоязычный, концепций для входа (`charter`, `.bvc`, `intent node`, `atom`, `trace`, `evidence`, `work item`) — около 15. Это **отбивает** пользователя в первые 10 минут.

## 4. Кто пользователь — открытый вопрос

| Сегмент | Подходит? | Почему |
|---|---|---|
| Разработчик-одиночка с Claude/Cursor | **нет** | Cursor решает «написать код» в 100× быстрее, без канона |
| Команда 3-10 разработчиков | **нет** | У них уже есть Linear + Cursor, моно-инструмент проигрывает по UX |
| Enterprise | **нет** | Нет SSO, audit, compliance, нет on-prem гарантий |
| Тех-лид, контролирующий «вайб-кодеров» | **возможно** | Реальная боль, но конкурент — Replit Teams / Devin Enterprise |
| 1C/OneBase разработчик | **возможно** | Уникальная ниша, никто не делает, но никаких 1С-сценариев пока нет |
| Сам автор | **да** | использование «на себе» работает |

Из 7 гипотез — только 2 живые, и обе **не подтверждены ни одним пользователем кроме автора**.

## 5. Кому это не нужно

- Кто пишет «однострочные фичи» — слишком много церемонии.
- Кто использует Cursor / Claude Code — у них уже есть rules + memories + agent.
- Кто хочет автономного агента «дай задачу — получи PR» — Devin / OpenHands ближе.
- Кто хочет понимание большой кодовой базы — Sourcegraph Cody / Augment делают лучше.
- Кто хочет команду + рабочий процесс — Linear + любой агент собирается за день.
- Кто работает не на русском — UX непонятен.
- Кто не готов учить .bvc / Work Graph канон.

Это **большинство рынка**.

## 6. Где Work Graph **выигрывает** у всех

Честно — две вещи:

1. **Полностью локальный, всё в git, никакой SaaS-зависимости.** Privacy / on-prem из коробки. Cursor шлёт в облако, Devin вообще облачный, Linear облачный, Copilot облачный.
2. **Канон смысла в `.bvc` — структура для намерения, которой ни у кого нет.** Потенциальный «Markdown 2.0 для разработки». Obsidian близко, но не делает execution.

Всё остальное — соревновательная функциональность, где Work Graph **проигрывает по очкам**.

## 7. Где Work Graph **проигрывает категорически**

| Конкурент | Что делает лучше | Что не догнать без огромных вложений |
|---|---|---|
| **Cursor / Windsurf** | подключение 60с, IDE-агент, языки, индексация | UX, скорость, экосистема, маркетинг |
| **Claude Code** | honest plan mode, скоупы, бесплатно с подпиской | brand trust |
| **Devin** | автономный, демо, PR в GitHub | автономность, бренд |
| **OpenHands** | открытый исходный код autonomous, сообщество | сообщество, скорость движения |
| **Aider** | CLI-симплисити, поддержка моделей | минимализм |
| **Linear** | task UX, скорость, интеграции, мобильное | весь PM-стек |
| **Sourcegraph Cody + Batch Changes** | enterprise scale, code-graph | enterprise sales |
| **GitHub Copilot Workspace** | plan→tasks→PR в GitHub | владение GitHub |
| **LangGraph / CrewAI** | гибкая оркестрация как библиотека | сообщество, экосистема |
| **Plandex** | plan-driven agent через CLI | минимализм |
| **Obsidian + LLM-plugins** | smysl + knowledge graph + сообщество | плагины, темы, рынок |
| **Notion AI** | database + AI + UX для не-разработчиков | UX, бренд |
| **Cursor Memories / mem0 / Letta** | project memory встроена | встроенность в основной рабочий процесс |

Неприятный факт: **Cursor + `.cursor/rules` + Memories + MCP** покрывает 70% того, что обещает Work Graph, и пользователь уже там.

## 8. Четыре честные позиции

Нынешняя позиция «всё сразу» не выживает. Нужно выбрать одну:

### A. Memory & рабочий процесс layer поверх Cursor / Claude Code

Не строить IDE, не делать своего агента. Быть **MCP-сервером**, добавляющим к Cursor: канон `.bvc`, workgraph, trace, memory. Конкуренция: Cursor Memories, mem0, Letta.
- **+** падающая планка входа, существующая аудитория
- **−** Cursor сам это допилит за 6 месяцев

### B. Agent управление для команд с LLM-агентами

Целевая аудитория — тех-лид, которому страшно, что junior с Cursor залил мусор в main. Канон + evidence + verified gate = audit для AI-кода. Конкуренция: Replit Teams, Devin Enterprise, LangSmith.
- **+** платёжеспособный сегмент, реальная боль
- **−** enterprise sales цикл, нужны интеграции с GitHub/GitLab/Bitbucket

### C. Vertical для 1С / OneBase

«Платформа для разработки конфигураций 1С через LLM с верификацией». Никто из big players 1С не делает. Аудитория — фирмы-франчайзи (RU/CIS, тысячи). ROI «1С-разработчик в 2× быстрее».
- **+** нет конкурентов, конкретный сегмент, заявленная domain vertical из charter, платёжеспособный рынок RU
- **−** ограничен 1С-миром, нужно знание 1С-сообщества и каналов

**Самый реалистичный путь, и он уже в charter.**

### D. Открытый канон — `.bvc` как стандарт

Без коммерческого продукта: `.bvc` спецификация + reference impl + CLI + open сообщество. Продукт позже, поверх стандарта.
- **+** возможно реально влиятельный артефакт
- **−** коммерциализация не очевидна, конкуренция с yaml/toml/markdown

## 9. Жёсткий вердикт

**Идея сильная, позиционирование отсутствует.** Продукт отвечает на «что я могу построить?» вместо «какая боль и кто платит?».

Тестовый вопрос: попроси одного знакомого разработчика (не из контекста проекта) посмотреть UI и за 5 минут сказать «что это и зачем мне?». Если он скажет «не понял» — это не его проблема, а сигнал, что продукт не сформулировал ценность.

Что в фундаменте реально ценно:
- канон `.bvc` (можно сделать стандартом);
- evidence-driven рабочий процесс (реальная боль рынка AI-кода);
- полная локальность (растущий запрос на privacy).

Что нужно отрезать или признать R&D:
- собственная IDE-оболочка;
- собственный orchestrator агентов;
- одновременная конкуренция с Cursor, Linear, Devin и Obsidian.

**Одна строка действия:** выбрать одну из 4 позиций (ставка — **C, 1С-vertical**), переписать `README.md` и `charter/main.bvc` под неё, спрятать всё остальное в `experimental/`, найти **одного** не-автора, который проведёт реальную задачу через эталонный сценарий. До этого момента всё остальное — улучшение R&D-стенда.
