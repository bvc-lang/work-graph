# AN-46: SDK агентов (Cursor, Claude, OpenCode) — что дают Work Graph и что входит в продукт

**Запрос:** «У Claude и Cursor, OpenCode и т.д. есть свои SDK — что они могут позволить сделать в WG, какую часть можно интегрировать и сделать частью продукта?»

**Связи:** [AN-44](competitor-analysis-vs-work-graph.md) (позиционирование и слои рынка), [AN-45](work-graph-sidebar-sections-guide.md) (разделы пульта), [AN-43](work-graph-npm-first-distribution.md) (распространение через npm), [docs/workgraph-mcp-client-strategy.md](../../docs/workgraph-mcp-client-strategy.md).

---

## Кратко

SDK у Cursor, Claude и OpenCode — это **«руки»**: запуск умного агента из скрипта, фона или облака. Work Graph — **«учёт и канон»**: задачи, захват, свидетельства, проверки, память в git.

Продукт WG — не «ещё один агент», а **подключение агента к репозиторию** (`@work-graph/mcp`) + **пульт** + **(опционально) оркестратор исполнителей**. Редактор и подписки на модели остаются у вендоров; WG не строит IDE.

Две стороны интеграции:

| Сторона | Кто «думает и пишет код» | Роль Work Graph |
|--------|--------------------------|-----------------|
| **Клиент** (Cursor, Claude Code, OpenCode в редакторе) | агент в привычной среде | источник правды о работе |
| **Исполнитель** (демон, CI, ночной прогон) | SDK/API агента | формирует контекст, запускает «руки», принимает результат в git |

---

## Две стороны: схема

```
  [ Cursor / Claude / OpenCode ]          [ Work Graph ]
         чат, правки, инструменты   ←→    бэклог, канон, проверки
                ↑                              ↑
                └──── SDK-исполнитель ─────────┘
                     (демон, фон, CI)
```

Конкуренты продают **исполнение**. WG должен быть слоем, к которому подключаются любые исполнители — без дублирования чата и без переноса статусов задач в сессию агента.

---

## Cursor SDK

### Что это

Пакет для запуска агента Cursor **из программы**: одноразовый запрос, сессия с продолжением, локально в папке проекта или в облачной копии репозитория; поток ответа, отмена, настройка подключённых серверов (в том числе Work Graph).

### Что уже есть в WG

Провайдер `cursor-sdk` в реестре исполнителей: Work Graph собирает промпт из задачи, памяти и целевых файлов, отдаёт агенту Cursor, нормализует ответ в **свидетельства** и запрос смены статуса. Включение через флаг окружения; ядро не привязано к Cursor API.

### Что даёт продукту

- **Фоновый исполнитель** — демон берёт задачу с доски, запускает Cursor-агента с уже подключённым `@work-graph/mcp`, результат пишет в git.
- **Облачный прогон** — тяжёлые эпики на виртуальной машине Cursor; учёт работ остаётся в репозитории.
- **Автоматизации** — ночной прогон очереди «готов», свидетельство после слияния ветки.

### Чего не делать

Не переносить бизнес-состояние в сессию Cursor. Не строить второй чат вместо редактора.

### Сравнение

| Только Cursor SDK | Cursor SDK + Work Graph |
|-------------------|-------------------------|
| код из скрипта | код **и** единый бэклог |
| «готово» = слова агента | «готово» = свидетельства + проверки |
| память сессии | память из закрытых задач |

## Claude (Agent SDK / API / Claude Code)

### Что это

Длинный контекст, структурированный вывод, вызов инструментов; терминальный агент с правилами проекта, хуками и подагентами.

### Что уже есть в WG

Провайдер `claude-sdk-api` — тот же контракт «вход/выход исполнителя», что у Cursor. Claude Code как **клиент** подключает тот же `@work-graph/mcp`, что Cursor.

### Что даёт продукту

- **Выбор исполнителя по задаче** — рассуждение и большой контекст → Claude; правки в IDE и shell → Cursor SDK.
- **Терминальный сценарий** — разработчик в Claude Code, Work Graph — единственный бэклог.
- **Строгие свидетельства** — заполнение блоков «анализ», «решение», «свидетельство» с проверкой формата.

### Чего не делать

Не дублировать заметки Claude Note: память WG только из **закрытых задач с проверкой**.

### Сравнение

| Claude Code + CLAUDE.md | + Work Graph MCP |
|---------------------------|------------------|
| правила проекта | правила **и** захват задачи |
| тесты по желанию | матрица обязательных проверок |
| нет `work.id` | атом смысла в git |

---

## OpenCode (SDK и MCP-мост)

### Что это

Открытый агент для кодинга: выбор модели (включая локальные), поддержка языковых серверов, несколько параллельных сессий, headless API. Отдельный MCP-мост позволяет Claude/Cursor **делегировать кодинг** OpenCode.

### Что в WG

Отдельного провайдера пока нет; архитектура готова — тот же слой, что `cursor-sdk` и `claude-sdk-api`.

### Что даёт продукту

- **Исполнитель без подписки Cursor** — политики «только открытое ПО / свои модели».
- **Локальные модели** — учёт и проверки в WG, кодинг через локальный движок.
- **Параллель** — несколько сессий OpenCode на подзадачи одного эпика; статус — на одной доске WG.

### Симметрия с рынком

OpenCode MCP делает OpenCode «руками» для Claude/Cursor. Work Graph стоит **рядом**: Claude ведёт задачи через WG, OpenCode пишет код — оба через один бэклог.

### Сравнение

| OpenCode + opencode-mcp | + Work Graph |
|-------------------------|--------------|
| делегирование кодинга | делегирование **с учётом задачи** |
| нет разбора → эпик | канон AN → эпик → атом |
| нет формальной готовности | свидетельства и проверка |

## Остальные инструменты (кратко)

| Инструмент | Как стыкуется | Роль в продукте WG |
|------------|---------------|-------------------|
| **Windsurf / VS Code + Copilot** | клиент + MCP | тот же `@work-graph/mcp`, без своего SDK в ядре |
| **Aider / локальный CLI** | близко к провайдеру `local-cli` | только allowlist-проверки, не полный агент |
| **Devin** | облачная VM + тикеты | WG — слой доказательств до/после PR |
| **Linear / Jira** | не SDK агентов | WG не заменяет PM; даёт атом в git + свидетельства |

## Что сделать частью продукта, а что — опцией

### Ядро (уже есть, довести до «установил и работает»)

| # | Компонент | Зачем |
|---|-----------|-------|
| 1 | **`@work-graph/mcp`** в npm | лицо продукта: Cursor / Claude / OpenCode / Windsurf — одна строка в конфиге |
| 2 | **Готовые сценарии** (`take_next_work_item`, `add_evidence`, `close_work_item`) | агент знает, что делать, без импровизации |
| 3 | **Пульт** (`npm run backlog:ui`) | доска, проверки, память — не чат |
| 4 | **`npx @work-graph/cli init`** | user-first установка (см. AN-43) |

### Слой исполнения (продукт для автопилота, не обязателен каждому)

| # | Компонент | Зачем |
|---|-----------|-------|
| 5 | **Реестр исполнителей** — local / openai / cursor-sdk / claude-sdk-api / *(будущий opencode-sdk)* | выбор «рук» по задаче |
| 6 | **Демон + живой цикл** | claim → SDK-агент с MCP WG → свидетельство → проверка → память |
| 7 | **Единые фасады** «проверить готовность» / «экспорт следа» | один вызов для агента и CI |

### Не продукт WG

- Подписки и модели Cursor / Anthropic / OpenCode.
- IDE, дифы, языковые серверы — у клиента.
- Облачные трекеры задач — WG их не обязан заменять.

## Общий вывод: чего не даёт рынок вместе

Типичный стек «Cursor + Linear + CI + Notion + заметки агента»:

- чат и код — в редакторе;
- задачи — в Linear;
- проверки — в CI;
- статьи — в Notion;
- память сессии — в заметках.

**Ни одно звено не ведёт цепочку целиком:** от разбора до доказательства в git и записи в памяти — один идентификатор задачи, без облачного трекера как источника правды.

SDK конкурентов — **двигатель**. Work Graph — **панель приборов и журнал полёта**. Продукт = **MCP-слой + пульт + (опционально) оркестратор SDK**, а не «ещё один агент».

## Рекомендации

| ID | Смысл |
|----|--------|
| **R1** | Продавать WG как **подключение к репозиторию + пульт**, не как IDE и не как маркетплейс «добавить WG». |
| **R2** | Cursor SDK и Claude SDK — **исполнители в реестре**; статус и память всегда в `.bvc` / журнале WG. |
| **R3** | Следующий провайдер — **OpenCode SDK** по образцу `cursor-sdk` (открытый стек, локальные модели). |
| **R4** | P0: npm + док «3 минуты в Cursor/Claude»; P1: live-путь cursor-sdk в демоне; P2: фасады `verify_gate` / `export_trace`. |
| **R5** | Не конкурировать с Cursor по UX чата; усиливать то, куда Cursor структурно не пойдёт: жёсткий канон, git, аудит AI-кода, вертикаль 1С (AN-44). |
