# AN-41: Упаковка Work Graph в exe — нужен ли «один файл как OneBase»

**Запрос:** «Стоит ли сделать, например, exe, как это сделал OneBase?» (см. [onebase.ivantitov.tech](https://onebase.ivantitov.tech/))

## Кратко

OneBase продаёт **платформу для конечного пользователя**: один Go-бинарник ~20 МБ, без Node, «скопировал — запустил». Это ядро их обещания.

Work Graph — **инструмент над git-каноном** (backlog, intent, MCP, Cursor). Основная аудитория — разработчик и оператор с репозиторием, не «бухгалтер без терминала».

**Рекомендация:** не копировать модель «onebase.exe в каждый проект». Сначала довести **гибрид C** из [AN-40](work-graph-project-deployment-model.md) (CLI, реестр, консоль-хост). **Exe имеет смысл позже** как **Work Graph Console** — один установщик **хоста** для всех проектов, а не runtime внутрь каждого репо.

---

## 1. Чем OneBase и WG разные

| | OneBase | Work Graph |
|---|---------|------------|
| Роль продукта | Платформа бизнес-приложений (справочники, документы, DSL) | Консоль управления работой и каноном в git |
| Аудитория | Пользователь без Node/1С | Разработчик, агент в Cursor, оператор backlog |
| Runtime | Сервер + веб-UI + конфигурация в одном бинарнике | Node-процесс + браузер на `:4177` + MCP |
| Канон | YAML/DSL в папке конфигурации | `intent/`, `charter/`, `architecture/main.bvc` в репо |
| Exe | ~20 МБ, без зависимостей — **главная фича** | Опциональная **упаковка** поверх npm/CLI |

У OneBase exe закрывает боль «не хочу ставить стек». У WG эту боль уже частично закрывает **один хост + переключатель проектов** (AN-40), а не отсутствие exe как таковое.

---

## 2. Три варианта для WG

### A — Exe «как OneBase» (полный аналог)

Один маленький бинарник, внутри сервер + UI, без Node снаружи.

| + | − |
|---|---|
| Узнаваемый паттерн «скачал — работает» | WG на Node; «~20 МБ без зависимостей» нереалистично |
| Удобно не-разработчикам | Переписывание стека (Go/Rust) — отдельный продукт, не упаковка |
| | Дублирует AN-40 вариант A: exe **в каждый** проект = N копий |

**Вердикт:** не цель. Не конкурировать с OneBase по форм-фактору runtime.

### B — Exe-лаунчер «Work Graph Console» (рекомендуется, если делать)

Один установщик **консоли-хоста**: внутри bundled Node (или embedded runtime) + `backlog:ui` + опционально WebView2 / системный браузер.

| + | − |
|---|---|
| Оператор без `npm install` и Node в PATH | Размер десятки–сотни МБ, не 20 |
| Один exe на машину, N проектов через реестр (AN-40) | Сборка, подпись, автообновление — отдельный контур |
| Совместимо с гибридом C | Windows pilot проще; macOS/Linux — второй этап |

**Вердикт:** имеет смысл **после** стабилизации CLI и multiproject host, не вместо них.

### C — Только npm / CLI (как сейчас)

`packages/work-graph-cli`, `npm run backlog:ui`, runbook.

| + | − |
|---|---|
| Минимум инфраструктуры релизов | Барьер для «чистого» оператора |
| Естественно для Cursor/MCP | Демо «как OneBase» слабее |

**Вердикт:** оставить **основным** каналом для разработчиков; exe — дополнение.

---

## 3. Когда exe оправдан

Делать упаковку, если выполняется **хотя бы одно**:

1. Есть 2–3 оператора **без Node**, которым нужна консоль WG регулярно.
2. Нужно демо/пилот «два клика — Work Graph», без объяснения npm.
3. AN-40 hybrid host в проде, а runbook всё ещё «слишком инженерный».

**Не делать сейчас**, если:

- Все пользователи уже в Cursor + MCP (exe им не нужен).
- Multiproject host и CLI ещё не закреплены — exe замаскирует дыры в onboarding, не исправит архитектуру.

---

## 4. Поэтапный план (если пойдём в B)

| Этап | Содержание |
|------|------------|
| **1 (сейчас)** | AN-40: CLI `init` / `register` / `ui`, реестр, переключатель, runbook |
| **2** | ADR «Work Graph Console»: WebView2 vs внешний браузер, bundled Node, автообновление |
| **3** | Windows pilot: `WorkGraphConsole.exe` → localhost:4177, ярлык в меню |
| **4** | macOS/Linux — по запросу; не блокировать Windows pilot |

Exe **не заменяет** `work-graph-cli` в репозитории — только стартует хост.

## 5. Связь с AN-40

| AN-40 | AN-41 |
|-------|-------|
| Где канон, где хост, как N проектов | **Как доставить хост** не-разработчику |
| Гибрид C — архитектура | Console exe — **упаковка** гибрида C |
| Exe в каждый репо = вариант A | Console exe = **один** хост на машину |
